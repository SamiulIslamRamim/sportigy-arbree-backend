Admin Login Implementation v2.0

Separate admin auth flow with hardcoded credentials — includes login, refresh, verify, and logout

1. Overview

The existing codebase had a user auth system that was dropped in the latest migration (all auth tables removed, auth routes commented out). We are adding a new admin login that follows the same architectural pattern as the old user login, but as a fully separate, independent flow.

What we're building

  • Hardcoded admin credentials for now: admin / amdin1234
  • 4 endpoints: login, refresh, verifySession, logout
  • Full refresh token rotation with httpOnly cookies, scoped to /admin
  • Separate middleware for route protection (checks role)
  • Structured so swapping to a DB table later requires only changing the controller
Files to create (4): controller, middleware, schema addition, type addition
Files to modify (2): routes/index.ts, utils/jwt.ts

3c. JWT Utilities src/utils/jwt.ts MODIFY

Reasoning: The existing generateAccessToken only signs { id } — it does not include role. Admin tokens must carry role: "admin" so the middleware can distinguish admin vs. user tokens.

// Add after generateRefreshToken
export const generateAdminAccessToken = (payload: { id: string; role: string }): string => {
  return jwt.sign(
    { id: payload.id, role: payload.role },
    process.env.JWT_SECRET as string,
    { expiresIn: "15m" }
  );
};

3d. Controller src/controllers/admin-login.controller.ts NEW FILE

Reasoning: Contains all 4 admin auth endpoints. Mirrors the existing user auth controllers exactly, but:

  • Hardcoded credentials (section marked // 🔁 SWAP TO DB)
  • Uses generateAdminAccessToken so role is embedded in the JWT
  • Cookie path is /admin (isolated from user tokens at /token)
import { Request, Response } from "express";
import {
  JwtRefreshPayload,
  AdminLoginBody,
} from "../types/auth.type.js";
import {
  generateAdminAccessToken,
  generateRefreshToken,
  verifyRefreshToken,
} from "../utils/jwt.js";

// ─── Admin Login ────────────────────────────────────────────────
export const adminLogin = async (req: Request, res: Response): Promise<void> => {
  try {
    const { username, password } = req.body as AdminLoginBody;

    // ── Hardcoded admin credentials — 🔁 SWAP TO DB ─────────
    const ADMIN_USERNAME = "admin";
    const ADMIN_PASSWORD = "amdin1234";

    if (username !== ADMIN_USERNAME || password !== ADMIN_PASSWORD) {
      res.status(401).json({ detail: "Invalid admin credentials" });
      return;
    }

    const accessToken = generateAdminAccessToken({ id: "admin", role: "admin" });
    const refreshToken = generateRefreshToken({ id: "admin" });

    res.cookie('refreshToken', refreshToken, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'lax',
      path: '/admin',
      maxAge: 7 * 24 * 60 * 60 * 1000,
    });

    res.status(200).json({
      access: accessToken,
      admin: { username: "admin", role: "admin" },
    });
  } catch (error) {
    console.error("Admin login error:", error);
    res.status(500).json({ detail: "Internal server error" });
  }
};

// ─── Admin Refresh ──────────────────────────────────────────────
export const adminRefresh = async (req: Request, res: Response): Promise<void> => {
  try {
    const refreshToken = req.cookies?.refreshToken;

    if (!refreshToken) {
      res.status(400).json({ detail: "Refresh token is required." });
      return;
    }

    let decoded: JwtRefreshPayload;
    try {
      decoded = verifyRefreshToken(refreshToken);
    } catch {
      res.status(401).json({ detail: "Refresh token invalid!" });
      return;
    }

    // 🔁 SWAP TO DB: replace with prisma.admin.findUnique
    if (decoded.id !== "admin") {
      res.clearCookie('refreshToken', { path: '/admin' });
      res.status(401).json({ detail: "Admin not found." });
      return;
    }

    const newAccessToken = generateAdminAccessToken({ id: "admin", role: "admin" });
    const newRefreshToken = generateRefreshToken({ id: "admin" });

    res.cookie('refreshToken', newRefreshToken, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'lax',
      path: '/admin',
      maxAge: 7 * 24 * 60 * 60 * 1000,
    });

    res.status(200).json({
      accessToken: newAccessToken,
      message: "Token refreshed successfully",
    });
  } catch (error) {
    console.error("Admin refresh error:", error);
    res.status(500).json({ detail: "Internal server error" });
  }
};

// ─── Admin Verify Session ───────────────────────────────────────
// Checks the refresh token cookie, validates admin, returns a new access token
export const adminVerifySession = async (req: Request, res: Response): Promise<void> => {
  try {
    const refreshToken = req.cookies?.refreshToken;

    if (!refreshToken) {
      res.status(401).json({ detail: "No session found." });
      return;
    }

    let decoded: JwtRefreshPayload;
    try {
      decoded = verifyRefreshToken(refreshToken);
    } catch {
      res.status(401).json({ detail: "Session expired." });
      return;
    }

    // 🔁 SWAP TO DB: replace with prisma.admin.findUnique
    if (decoded.id !== "admin") {
      res.clearCookie('refreshToken', { path: '/admin' });
      res.status(401).json({ detail: "Session expired." });
      return;
    }

    const newAccessToken = generateAdminAccessToken({ id: "admin", role: "admin" });

    res.status(200).json({
      accessToken: newAccessToken,
      admin: { username: "admin", role: "admin" },
    });
  } catch (error) {
    console.error("Admin verify session error:", error);
    res.status(500).json({ detail: "Internal server error" });
  }
};

// ─── Admin Logout ───────────────────────────────────────────────
export const adminLogout = async (req: Request, res: Response): Promise<void> => {
  try {
    res.clearCookie('refreshToken', {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'lax',
      path: '/admin',
    });

    res.status(200).json({ message: "Logged out successfully." });
  } catch (error) {
    console.error("Admin logout error:", error);
    res.status(500).json({ detail: "Internal server error" });
  }
};
⚠️ Cookie path = /admin (not /admin/token): The cookie path determines which routes the browser sends the cookie to. If you set path: '/admin/token', the browser only sends the cookie to URLs starting with /admin/token. But adminVerifySession is at GET /admin/token/verify/ — the browser would send it.

However, path: '/admin' is safer and more flexible — it covers /admin/token/, /admin/token/refresh/, /admin/token/verify/, and any future admin routes like /admin/dashboard.

3e. Middleware src/middleware/admin-auth.ts NEW FILE

Reasoning: Same as auth.ts but adds a role === "admin" check to prevent user tokens from accessing admin endpoints.

import { Response, NextFunction } from "express";
import { verifyAccessToken } from "../utils/jwt.js";
import { AuthenticatedRequest } from "../types/auth.type.js";

export const authenticateAdmin = (req: AuthenticatedRequest, res: Response, next: NextFunction): void => {
  const authHeader = req.headers.authorization;

  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    res.status(401).json({ detail: "Authentication credentials were not provided." });
    return;
  }

  const token = authHeader.split(" ")[1];

  if (!token) {
    res.status(401).json({ detail: "Token not found." });
    return;
  }

  try {
    const decoded = verifyAccessToken(token);

    // ── Extra guard: only admin role allowed ────────────────
    if (decoded.role !== "admin") {
      res.status(403).json({ detail: "Admin access required." });
      return;
    }

    req.user = decoded;
    next();
  } catch (error) {
    res.status(401).json({ detail: "Token is invalid or expired." });
  }
};

4. End-to-End Flows

Login → POST /admin/token/
Request:  { "username": "admin", "password": "amdin1234" }
Response: 200
  Set-Cookie: refreshToken=<token>; Path=/admin; HttpOnly; SameSite=Lax
  Body: { "access": "<jwt>", "admin": { "username": "admin", "role": "admin" } }
Verify Session → GET /admin/token/verify/
Request:  Cookie: refreshToken=<token>
Response: 200
  Body: { "accessToken": "<newJwt>", "admin": { "username": "admin", "role": "admin" } }

→ Used on page load / app init to check if the admin session is still valid.
Refresh → POST /admin/token/refresh/
Request:  Cookie: refreshToken=<token>
Response: 200
  Set-Cookie: refreshToken=<newToken>; Path=/admin; HttpOnly; SameSite=Lax
  Body: { "accessToken": "<newJwt>", "message": "Token refreshed successfully" }

→ Called when the access token is about to expire (401 interceptor).
Logout → POST /admin/token/logout/
Request:  (any)
Response: 200
  Set-Cookie: refreshToken=; Path=/admin; Expires=Thu, 01 Jan 1970
  Body: { "message": "Logged out successfully." }

5. Why Separate Endpoints?

EndpointWhy admin can't reuse the user version
verifySession Reads cookie from path: '/token' — admin cookie is at /admin.
Queries prisma.user.findUnique — admin has no DB entry (yet).
Calls generateAccessToken(user) — doesn't include role.
logout Clears cookie from path: '/token' — won't touch the admin cookie at /admin.
